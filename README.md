# Remote Working

**텔레그램 봇 하나 ↔ 로컬 프로젝트 하나. 작업 하나 ↔ Codex 영구 대화 하나.**

여러 허용 사용자가 개인 채팅으로 개발을 요청하고, 운영자는 같은 로컬 환경의 Codex 앱에서 작업별 대화를 확인하는 범용 CLI입니다. 프로젝트 경로와 봇 토큰은 나중에 설정합니다. 기본 실행에 별도의 웹 서버나 공개 포트는 필요하지 않습니다.

## 준비

- Node.js **22.13 이상** (`node:sqlite` 사용; Node 22에서는 실험 기능 경고가 나올 수 있음).
- 로그인되어 실행 가능한 Codex CLI/app-server.
- 나중에 연결할 Telegram BotFather 봇 토큰, 관리자와 허용 사용자의 **숫자 Telegram 사용자 ID**.
- 공유 대상은 신뢰할 수 있는 협업자입니다. 공개 불특정 다수용 서비스가 아닙니다.

```sh
npm ci
npm run build
npm test
```

## 나중에 설정해서 실행

```sh
npm start -- init my-project
```

`~/.remote-working/my-project/config.json`에 템플릿을 만듭니다. 기존 설정은 덮어쓰지 않습니다. 토큰 없이 실행할 수 있는 명령입니다.

```json
{
  "name": "my-project",
  "projectPath": "/absolute/path/to/project",
  "tokenEnv": "TELEGRAM_BOT_TOKEN",
  "adminIds": [123456789],
  "allowedUserIds": [234567890],
  "codexPath": "/absolute/path/to/codex",
  "workspace": "project"
}
```

- `name`: init에 사용한 연결 이름. 연결마다 다른 이름을 사용합니다.
- `projectPath`: 봇이 사용할 프로젝트의 절대 경로.
- `tokenEnv`: 토큰 값이 아니라 **토큰이 들어 있는 환경변수 이름**.
- `adminIds`: 모든 작업 조회와 실행 승인 권한. 최소 한 명 필요.
- `allowedUserIds`: 본인 작업을 요청·조회·중단할 사용자. 관리자는 자동 허용. 관리자도 봇에 먼저 메시지를 보내야 승인 알림을 받을 수 있습니다. 봇의 `/whoami`로 자신의 숫자 ID를 확인할 수 있습니다.
- `codexPath`: 설정 생성 시 실행 가능한 설치 경로를 탐색합니다. 깨진 전역 CLI가 있으면 앱 번들 경로를 먼저 사용합니다. 앱 업데이트 후 `doctor`로 재확인하세요.
- `model`: 선택 항목. 생략하면 Codex 설정을 따릅니다.
- `workspace`: `project`(기본) 또는 `worktree`.

토큰은 비밀 관리자나 현재 셸에서 환경변수로 주입합니다. 예를 들어 zsh에서는 화면과 셸 이력에 토큰을 직접 쓰지 않고 입력할 수 있습니다.

```sh
read -rs 'TELEGRAM_BOT_TOKEN?Telegram bot token: '
export TELEGRAM_BOT_TOKEN
npm start -- doctor my-project
npm start -- start my-project
```

종료는 실행 터미널의 **Ctrl+C**입니다. 현재 버전은 포그라운드 장기 실행 프로그램이며 OS 자동 시작 서비스는 설치하지 않습니다. 상시 실행에는 운영 환경의 프로세스 관리자를 사용하세요.

```sh
npm start -- status my-project
```

선택적으로 `npm link` 후 `remote-working init my-project`처럼 실행할 수 있습니다. 테스트와 설치는 Telegram 메시지를 보내지 않습니다. 실제 봇은 `start`에서만 연결합니다.

## 작업 규칙

```text
새 작업: 로그인 오류 수정해줘
→ #1 작업과 [TG #1 · 사용자] 로그인 오류 수정해줘 대화 생성

구글 로그인에서도 발생해
→ 현재 작업의 후속 요청. 실행 중이면 대기 후 순차 처리

테스트 통과했으면 커밋하고 브랜치에 푸시해줘
→ 같은 대화에 전달. 필요한 도구 승인은 관리자에게 전달

새 작업: 검색 기능 추가해줘
→ #2와 별도 Codex 대화 생성

1번 이어서
→ 현재 작업을 #1로 변경
```

| 명령                           | 기능                                                     |
| ------------------------------ | -------------------------------------------------------- |
| `새 작업: 내용` / `/new 내용`  | 새 작업 생성                                             |
| `/whoami`                      | 본인의 Telegram 숫자 ID 확인 (작업 권한은 부여하지 않음) |
| `작업 목록` / `/tasks`         | 접근 가능한 최근 작업 30개                               |
| `42번 이어서` / `/use 42`      | 현재 작업 선택                                           |
| `진행 상황` / `/status`        | 현재 작업 상태와 Codex thread ID                         |
| `중단해줘` / `/stop`           | 봇이 실행 중인 현재 작업의 중단 요청                     |
| `/approve 번호` / `/deny 번호` | 관리자만 현재 도구 요청 승인·거부                        |
| `/answer 번호 답변`            | 질문에 답변. 여러 질문이면 ID→문자열 JSON                |

작업 메시지에 답장하면 해당 작업으로 연결합니다. 일반 메시지는 사용자·채팅별 현재 작업에 연결됩니다. 명시적 새 작업은 수신 즉시 번호를 예약하고 후속 입력의 대상도 수신 시 기록합니다. 선택을 나중에 바꿔도 이미 받은 후속 입력의 작업은 바뀌지 않습니다.

일반 입력의 연관성, 잘못된 작업 참조, 모호한 입력은 별도의 임시 Codex 대화에서 LLM이 안내합니다. LLM은 안내와 분류만 하며, 접근 권한과 실제 작업 번호 검증은 프로그램이 수행합니다. 이 분류도 Codex 사용량을 소비합니다. LLM 장애 시 정해진 한국어 도움말로 안내합니다. 모든 오입력 경로를 LLM에 의존하지는 않습니다(권한 거부, 만료된 승인 등은 프로그램이 즉시 설명).

새 작업의 경계를 추측해 기존 작업을 몰래 교체하지 않습니다. 현재 작업과 다른 요청이면 명시적 `새 작업:`으로 확인합니다. 현재 작업이 없고 독립적인 개발 요청이라면 LLM 분류에 따라 새 작업을 시작할 수 있습니다.

## Codex 앱에서 보기

같은 로컬 사용자와 Codex 상태 저장 환경에서 실행하고, 앱에 등록된 프로젝트 경로를 설정하세요. `ephemeral: false`로 생성한 작업 대화는 아래와 같이 이름을 붙입니다.

```text
[TG #42 · 민수] 로그인 오류 수정
```

프로젝트 루트를 cwd로 사용한 대화가 앱의 해당 프로젝트 아래에서 다시 조회되는 것은 이 개발 환경에서 실측했습니다. 모든 앱/CLI 버전이나 원격 서버의 자동 동기화를 보장하지 않습니다. `CODEX_HOME`을 다른 경로로 분리하면 앱과 이력이 분리될 수 있습니다. 봇 DB와 Codex 이력은 별개이므로 둘 다 보존하세요.

앱에서 대화를 직접 실행하는 동안 같은 대화를 봇이 이어 실행하지 않도록 시작 전 활성 상태를 검사합니다. 이는 서로 다른 프로세스 사이의 원자적 잠금이 아닙니다. 앱에서 수정할 때는 봇 실행을 중단하고 작업을 인계하세요.

## 파일 작업·Git·배포

- **기본 `project`:** 설정된 프로젝트 폴더에서 순차 실행합니다. 앱 표시가 검증된 방식이며 별도 브랜치를 자동 생성하지 않습니다. 기존 미커밋 변경과 수동 작업을 함께 수정하지 않도록 운영하세요.
- **선택 `worktree`:** Git 저장소의 HEAD에서 `remote-working/<연결>/<작업번호>` 브랜치와 독립 worktree를 만듭니다. 기존 미커밋 변경은 복사하지 않습니다. worktree는 자동 삭제하지 않습니다. 이 모드의 앱 프로젝트 그룹 분류는 사용 환경에서 검증해야 합니다.
- 커밋·푸시·배포는 사용자가 명시적으로 요청한 경우 Codex가 프로젝트의 기존 명령과 지침을 따라 수행합니다. CLI 자체가 고정된 CI/CD 어댑터나 자동 롤백을 제공하지는 않습니다. 배포 설정과 기존 스크립트가 프로젝트에 필요합니다.
- Codex `workspace-write` + `untrusted` 승인 정책을 사용합니다. Codex가 요청한 승인만 관리자에게 전달합니다. 모든 셸 명령을 별도로 심사하거나 Git/배포 권한을 완전히 격리하는 정책 엔진은 아닙니다.
- 승인 요청은 10분 후 만료되고, 특정 서버 요청에 한 번만 적용됩니다. 재시작 이후 이전 승인 번호는 사용할 수 없습니다.
- 승인 전에 실제 명령·작업 경로·권한 범위를 확인하세요. 특히 운영 배포를 공유할 때는 CI 쪽 보호된 환경/승인을 추가하세요.
- 작업 요청자의 역할은 대화 접근을 제한하지만 Codex의 로컬 계정·기존 MCP 도구 권한 전체를 격리하지 않습니다. 전용 OS 사용자/실행 환경이 필요한 배포에서는 별도로 구성해야 합니다.
- 봇 토큰 환경변수는 자식 Codex 프로세스에서 제거합니다. 토큰은 설정 파일이나 DB에 저장하지 않습니다. 다른 상속 환경변수나 Codex 자체 인증은 실행 환경의 관리 대상입니다.

## 복구와 운영 특성

- 같은 봇 토큰, 같은 프로젝트 실제 경로, 같은 연결 설정의 중복 실행을 SQLite 잠금으로 차단합니다. 프로세스가 비정상 종료되어도 OS가 잠금을 해제합니다. 실행 중인 잠금 파일은 삭제하지 마세요.
- 수신 업데이트를 SQLite에 영구 저장한 뒤 Telegram offset을 진행시킵니다. 동일 update ID는 재처리하지 않습니다.
- 결과가 불명확한 `processing` 요청은 재시작 때 `needs_review`로 표시하고 자동 재실행하지 않습니다. 따라서 장애 경계에서 exactly-once 실행을 보장하는 대신 중복 커밋/배포를 피하도록 보수적으로 멈춥니다.
- 작업 시간 제한 또는 Codex 연결 종료 시 실행을 중단하고 상태 확인을 요구합니다. 완료가 확인된 마지막 turn은 복구 시 결과를 재전달합니다.
- 발신 메시지는 outbox에 저장하고 네트워크 오류 시 재시도합니다. 차단/미시작 등 영구 전송 오류는 실패로 보존하고 다음 메시지로 진행합니다. Telegram 전송 직후 DB 저장 전에 프로세스가 종료되면 알림이 중복될 수 있습니다.
- 중단은 실행 취소 요청이며 이미 수정한 파일, 완료한 커밋, 시작된 외부 배포를 되돌리지 않습니다.
- 현재는 개인 채팅의 텍스트 요청을 지원합니다. 그룹/첨부/음성은 지원하지 않습니다.
- app-server는 실험적 인터페이스입니다. 앱 업데이트 후 `doctor`, 테스트와 실제 작은 작업으로 호환성을 확인하세요.

상태 파일은 `~/.remote-working/<연결>/state.sqlite`, 설정은 `config.json`에 저장합니다. `REMOTE_WORKING_HOME`으로 봇 상태 루트만 바꿀 수 있습니다. Codex 상태 경로를 자동 변경하지 않습니다.

## 개발 및 검증

```sh
npm test
npm run format:check
npm run smoke:codex
```

`smoke:codex`는 실제 로그인된 Codex로 임시 대화를 생성하고 단일 응답을 검증합니다. 토큰 사용량이 발생할 수 있지만 Telegram은 연결하지 않고 프로젝트 파일을 수정하도록 요청하지 않습니다.

소스 구성:

- `cli.ts`: 설정 템플릿·실행·상태·진단 명령
- `src/config.ts`: 연결별 설정 검증과 실행 파일 탐색
- `src/rpc.ts`: app-server JSONL RPC, 응답/이벤트, 시간 제한
- `src/service.ts`: 작업 큐·LLM 안내·승인·질문·복구
- `src/store.ts`: SQLite 수신함·발신함·작업·메시지 연결
- `src/router.ts`: 명시적 명령과 권한 검증
- `src/telegram.ts`: Bot API long polling과 메시지 전송
- `src/workspace.ts`: 선택적 Git worktree 생성

공식 참고: [Codex app-server](https://learn.chatgpt.com/docs/app-server), [Telegram Bot API](https://core.telegram.org/bots/api).
